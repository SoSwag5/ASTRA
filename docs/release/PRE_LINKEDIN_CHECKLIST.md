# Before you announce ASTRA on LinkedIn

Use [v1.1.0-beta.2 from GitHub](https://github.com/SoSwag5/ASTRA/releases/tag/v1.1.0-beta.2).
Its exact-source/artifact checks and Owner release decision are complete.
The public download matches the approved ZIP. Automated verification does not
replace the new-user and another-PC checks below.

## Test it as a new user

- [ ] Download the built release ZIP from GitHub; select the named ASTRA ZIP,
      not Source code. Compare the ZIP checksum with the release checksum.
- [ ] On another Windows PC, Extract All into a fresh local folder outside
      OneDrive. Follow START HERE.html without help. Record any confusing step.
- [ ] Install Python if needed, run Install ASTRA.bat and wait for Ready.
      Run Open ASTRA.bat. No Git, Node, API key or paid AI should be needed.
- [ ] The browser opens `http://localhost:8787/`. If a bookmark opens `/demo`
      or `?demo=1`, replace it with the root address. Choose Use my own CV
      to leave the demo. Set the root address as your browser bookmark.
- [ ] Import one fictional PDF. Check name, summary, every skill, experience,
      projects, education and courses. Correct omissions before confirmation.
      Try the other majors in separate disposable workspaces.
- [ ] Skip the optional Excel tracker. Choose custom target titles or technical
      tracks deliberately. Save the focus; no careers should be auto-selected
      from incidental CV keywords. Keep rule-based matching.
- [ ] Click Start scanning on the left. Add one supported public company board.
      Press Start scanning now, read the preview, and Cancel once: no scan
      should run. Then preview again and Confirm and start scan.
- [ ] Check completed results, source errors and the original employer links.
      Review location, seniority and eligibility separately from fit. A score
      is not a success probability. Record irrelevant results with fictional examples.
- [ ] Start a second deliberately approved scan and press Stop. Confirm it ends
      cancelled; a source already in progress may finish first. Reopening ASTRA
      must not restart scanning automatically.
- [ ] Search elsewhere opens useful manual searches. Those sites are not
      automatically scanned or applied to by ASTRA.
- [ ] Prepare one application and inspect the documents. Check factual claims,
      dates and formatting against the fictional source. Apply manually only
      if you deliberately intend to use a real employer's website.
- [ ] Record a fictional application/follow-up, run this folder's stop.bat,
      reopen ASTRA and confirm the records persist. Closing a browser tab alone
      does not stop the app. Keep Gmail disconnected and optional AI off initially.
- [ ] Check light/dark, a narrow window, Tab/Shift+Tab, visible focus, reduced
      motion, loading/empty/error messages, and any broken buttons or links.
- [ ] Check that public screenshots contain only made-up data. Remove contact
      details, local paths, tokens, mailbox contents and real application records.
- [ ] Record the tester, date, Windows/Python versions, beta version and exact
      ZIP checksum plus PASS/FAIL for each step. Another-PC acceptance is not
      complete until someone actually performs it.

## Check the post

- [ ] Open the download link while signed out. Confirm the version and files
      match the post, and install from that downloaded ZIP.
- [ ] Say **early beta**, mention Windows/Python requirements, and explain
      the current discover → review → prepare → track → manual-apply workflow.
- [ ] Say scans are **manually confirmed**, not automatic daily scans. A daily
      job-search habit is different from a background scheduled scanner.
- [ ] Use security terms with evidence: Secure SDLC, threat modeling, scoped
      NIST SSDF / OWASP ASVS / OWASP SAMM mappings, SAST, SCA, SBOM, artifact
      integrity, GitHub CI/CD, regression testing and release assurance. Claim
      verified signed provenance only for the artifact whose check passed.
- [ ] Do not claim certification, compliance, an ASVS/SLSA level, universal
      matching accuracy or measured AI improvement. Distinguish your design,
      testing and assurance work from AI-assisted implementation.
- [ ] Keep comparisons, internal review prompts and unfinished research off
      the customer-facing release page. Link technical evidence separately.
- [ ] Give one useful next step: download the beta, try fictional data and
      report a reproducible issue. Do not publish unresolved release blockers.

If a cosmetic improvement takes repeated attempts, log it and freeze it for a
later patch. Failed install, data loss, privacy exposure, broken confirmation,
incorrect artifacts or mandatory security-gate failures remain blockers.
