# Windows installation assurance and task migration
Reference runtime: Python 3.13.2, Windows x64. Python 3.14 is a CI verification target; it is not called primary or continuously verified before successful remote matrix runs. Node 24 is needed for source builds, not a ZIP with prebuilt frontend. Python installation is a documented prerequisite; setup.bat does not install the Python interpreter.

The automated clean-install harness uses a fresh temporary directory, refuses unexpected archive paths/private files, calls setup.bat, starts the extracted application with synthetic data, checks empty DB, creates one fictional record, restarts and verifies persistence, then starts demo-only and verifies /demo=200 and all API paths denied. It stops only its own child process and removes only its temporary workspace. On a GitHub-hosted Windows runner this provides clean-runner evidence. A same-host run is only a rehearsal and must not be labeled clean VM evidence.

setup.bat does not register a scheduled task. Runner Python/Node setup covers prerequisites; an interactive Python installer, corporate endpoint restrictions, antivirus prompts and end-user GUI walkthrough remain separate manual acceptance cases where relevant. Do not use the live database or alter the live scheduled task.

Recommended future name: ASTRA Local Discovery. Existing task naming is retained until an approved migration. Before migration: record existing task definition privately, confirm executable/working directory, disable the old task, register the generic name, run one controlled disposable-data check, verify next run, then remove old registration. Roll back by removing new task and re-enabling old definition. Registering a second task without disabling the old one risks duplicate discovery. Owner approval is required before any live task change.
